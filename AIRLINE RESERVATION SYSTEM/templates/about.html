College Project (AIDS - 2nd Year)

✈️ Airline Reservation System Architecture

A real-world full-stack web application designed to demonstrate the convergence of Database Systems, Discrete Mathematics, Data Structures, and Object-Oriented Programming.

1. Double-Booking Prevention

Zero Seat Collision Guarantee

In traditional web systems, concurrent requests can read the same seat as available and book it simultaneously (Race Condition).

Solution: 4-tier defense architecture:
  • Frontend: Real-time visual seat map showing occupied seats as disabled.
  • Backend: Availability pre-check before processing payment/booking.
  • Transaction Isolation: Explicit database row-level locking (SELECT ... FOR UPDATE) within ACID transaction boundaries.
  • Database Unique Index: A virtual generated index on (flight_id, active_seat_flag) where only active bookings hold a non-null seat flag. Even in sudden simultaneous execution, MySQL strictly rejects duplicate active allocations with error 1062, triggering automatic rollback.

2. Configurable Overbooking Policy

Dynamic Capacity Management

Commercial airlines expect a 5-10% historical passenger no-show rate. Uncontrolled overbooking causes denied boarding; zero overbooking causes empty seats.

Solution: Configurable percentage formula:
Cmax = ⌊ Cphys × (1 + pover / 100) ⌋
  • Confirmed: Physical seat allocated while active bookings < Cphys.
  • Waitlisted: Active bookings reach Cphys but remain ≤ Cmax. FIFO queue position assigned.
  • Automatic Promotion: When a confirmed booking is cancelled, the earliest waitlisted passenger is automatically promoted to confirmed status and assigned the freed seat.
